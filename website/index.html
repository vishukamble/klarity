Root-Cause Extraction

No more digging through 30-line stack traces. klarity parses Java, Python, and Go logs to extract the exact error instantly.

⚡

Multi-Cluster Native

Go-routines scan your entire kubeconfig in parallel. Environments (prod, staging) are auto-detected by context naming.

🛡️

Strictly Read-Only

Perfectly safe for production. klarity only performs `get` and `list` operations.

⚙️

YAML Native

Simple, human-readable config that lives in your home directory.

v1.0.4

What's new

Performance

Instant results, even mid-interval

klarity now caches your last scan. Run it anytime — results appear instantly from cache while a fresh scan runs in the background. If anything changed, the screen refreshes automatically.

$klarity
klarity scan — 2026-03-23 15:35:59 UTC  (cached 4m ago, scanning...)
Environments: 1 | Clusters: 1 scanned | Issues: 3 found
✓Refreshed — still 3 issues found
Observability

Scan history, always on

Every scan is logged to ~/.klarity.log. Review past runs with --history.

$klarity --history

Diagnostics

New error pattern: missing required flags

klarity now extracts clean one-line summaries from Go structured logs — including kube-apiserver startup failures caused by missing required flags.

Raw log: E0323 14:37:32 run.go:74] "command failed" err="[service-account-issuer is a required flag, service-account-key-file is a required flag...]"
klarity shows: command failed: service-account-issuer is a required flag (and 2 more)
